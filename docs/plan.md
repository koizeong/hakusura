# ハクスラCOOP RPG 企画書

2026年10月22日 時点

## コンセプトと決定事項

放置で集めた手札から「僕が考えた最強ビルド」を組み、仲間とリアルタイムで高難度ボスに挑む、見下ろし型のハクスラCOOP RPG。

| 項目 | 決定 |
| --- | --- |
| 視点 | 2D見下ろし型(ディアブロ系) |
| 戦闘 | 作戦に従って自動で戦うオート戦闘。プレイヤーは移動で弾を避け、切り札を切る(ゆるい弾幕) |
| COOP | リアルタイム、2〜4人想定 |
| プラットフォーム | ブラウザ(PC・スマホ) |
| 開発 | Claude Code |

プレイの軸は「偶然の組み合わせのひらめき」と「それが通用したときの達成感」。一見なぜあるのか分からないスキル同士が噛み合って高火力が出る瞬間を、何度も味わえるようにする。

設計の大原則は「放置は幅、ビルドは深さ」。放置で増えるのは選択肢であり、高難度を越えられるかは組み合わせで決まる。

### 世界観

荒廃し切った、退廃的で閉鎖的な世界。誰もが死を待つばかりの鬱屈した空気が漂う。参考はKenshiやソウル系。

- 剣・魔法・銃が混在し、どれも等しく粗末で、等しく致命的
- 希望を語らない。救済よりも「今日を生き延びた」ことが報酬になるトーン
- 色は灰・錆・褪せた赤を基調にし、派手な属性エフェクトだけが暗い画面で際立つ
- 世界観とシステムを結びつける:腐敗・呪い・飢え・灰といった状態を、そのままビルドの部品として使う

## コアループ

放置で手札を増やし、厳選してビルドを組み、自分の操作で高難度ボスに挑む。この4段階を回し続ける。

```
1. 放置 ──(手札が増える)──▶ 2. 厳選とビルド
                                 │ 挑戦 ▲ 敗北で組み替え
                                 ▼      │
4. 報酬 ◀──(勝利)──────────── 3. 高難度戦闘
   └──▶ 次の放置へ
```

敗北したら放置に戻らず、すぐビルドを組み替えて再挑戦できる。この小さなループが「最強ビルド」を考える時間になる。

## ビルドシステム

ビルドの組み合わせは、タグ・トリガー・変換・ユニークの4層を掛け合わせて生む。数値の大小ではなく、組み合わせ方で強さが変わる作りにする。

| 層 | 役割 | 例 |
| --- | --- | --- |
| タグ | スキル・装備の性質を表すラベル | 火、雷、投射、範囲、召喚、近接、持続 |
| トリガー | 条件で別の効果を自動発動 | クリティカル時に雷撃、被弾時に氷の盾 |
| 変換 | ある性質を別の性質として扱う | 火ダメージの50%を雷に変換、召喚物が投射扱い |
| ユニーク | ルールそのものを壊す装備 | 回避不可だが被ダメ半減、スキル枠1つで全タグ発動 |

- タグを参照する補正は「〇〇タグのスキル+X%」の形に統一し、新スキル追加時に既存の装備が自動で絡むようにする
- トリガーの連鎖には上限(例:1回の発動から3段まで)を設け、無限ループを防ぐ
- ビルドを保存・共有できるコード形式を用意し、「最強ビルド」の見せ合いをしやすくする

### ビルド枠の構成(暫定)

1つのビルドは、スキル15枠(パッシブ専用6+兼用9)と装備9枠で組む。兼用枠をアクティブとパッシブにどう配分するかも、ビルドの選択肢になる。

| 枠 | 数 | 中身 |
| --- | --- | --- |
| パッシブ専用 | 6 | 常時効果、またはトリガーで自動発動する効果 |
| 兼用 | 9 | アクティブ・パッシブのどちらでも入れられる |
| 防具 | 4 | 頭、体、手、足 |
| 装飾品 | 3 | 装飾品1〜3 |
| 武器 | 2 | 1つ装備で両手持ち、2つ装備で二刀流 |
| 切り札 | 1 | 長いクールダウンの手動スキル |

- **両手持ちと二刀流:**どちらの持ち方かもタグとして扱い、「両手持ちのとき」「二刀流で左右の属性が違うとき」などを条件にできる。持ち方ごとの補正は試作では仮に、両手持ちが近攻撃+25%、二刀流がクールダウン-15%。スキルにも「二刀流向け」のタグを付けられる
- **アクティブの数:**アクティブは最大6個(暫定)。兼用枠の残り3つ以上は必ずパッシブになるため、パッシブは最低9個、最大15個になる。上限の数は試作で作戦の行数とあわせて確かめる

### 武器とスキルの棲み分け

攻撃の速さ・範囲・近接か遠距離か・属性は**武器**が持ち、アクティブスキルは武器をどう使うかの**技**にする。同じ技でも、持つ武器で中身が変わる。

| 持ち主 | 持つもの | 例 |
| --- | --- | --- |
| 武器 | 近接/遠距離、属性、威力、攻撃の間隔、振りかぶり、射程、扇の角度(弾なら弾速) | 鉄の剣:近接・斬・威力38・間隔0.85秒・射程100・扇130° |
| 技 | 使える武器の条件、武器の数値に掛ける倍率、形(振る・撃つ・周りに放つ) | 薙ぎ払い:近接の武器で、扇180°・威力0.9倍・間隔1.3倍 |

- **条件:**「近接の武器」「遠距離の武器」「雷の武器」「斬の近接の武器」のように、武器の種類と属性で決める。合う武器がなければその技は出ない
- **どの武器で出すか:**条件に合う武器で出す。二刀流で両手とも合うなら左右交互に出す。武器がなければ素手で出す
- **名前:**内訳では「鉄の剣の薙ぎ払い」のように、武器と技を合わせて呼ぶ。同じ技でも武器ごとに効き方が見える
- 付与(塗油)・切り札・敵のスキルは、技ではなく自分で数値を持つ
- 近接の武器は遠距離の武器より火力を高くする(DPSで1.6倍以上)

#### 能力値による条件

武器と技は、必要な能力値(筋力・技量・理力・信仰)を持つ。重い武器ほど筋力、細い武器や突き・連射ほど技量、雷の技は理力、火の技や塗油は信仰を求める。

- **足りなくても使える:**足りない1点ごとに威力-8%・攻撃の間隔+4%。武器と技の両方で足りなければ合わせて数える。低い能力値で無理に重い武器を振るビルドも作れる
- **基礎値として効く:**能力値そのものがキャラの強さになる。筋力は近攻撃、技量は攻撃の間隔、理力は雷、信仰は火、体力は最大HPを上げる。あくまで基礎値なので、1点の効き目は小さく(筋力1点で近攻撃+1.2%など)、全てを1つに振ってもビルドの方がずっと大きく効く
- **レベルで増える:**レベルは50が上限。Lv1で3点、1レベル上がるごとに1点増え、Lv50で52点。経験値は遠征で得る
- **振り直しはできない:**振った点は戻せず、振り方がそのキャラの個性になる。違う振り方を試すなら、キャラを増やす
- 重量・残弾・正気度は振り分ける値ではなく、戦闘中に変わる値として後で入れる

### 操作方式

スキルは「作戦」に従って自動で出る。プレイヤーの指は移動と切り札に使い、スマホのブラウザでも片手でぽちぽち遊べるようにする。敵の弾は遅く読みやすい「ゆるい弾幕」にして、移動で避ける楽しさを残す。

| 操作 | スマホ | PC |
| --- | --- | --- |
| 移動 | 押して引く(浮きスティック)、地面をタップでそこへ歩く | W A S D、マウスでも同じ |
| 狙う相手の指定 | 敵をタップ(もう一度で外す) | 同じ |
| 切り札 | 右下のボタン | Space |
| 早送り | 右上のボタン(×1〜×3) | 同じ |
| ダメージ内訳 | 右上の「勘定」 | Tab |

- **作戦:**「〈条件〉なら〈スキル〉」の行を並べ、上から順に見て、条件に合い使えるものを1つ使う。届かなければ寄っていく。条件は条件文と同じ部品(状態・天候・付与・強化など)で書き、ビルドの一部として組む
- **移動はすいすい:**攻撃中も足は止まらない。当たり判定は見た目より小さくし、弾の間を抜けられるようにする
- **切り札:**ビルドに1つ入れる、長いクールダウンの手動スキル。天候を変える・床を敷く・周りを一斉に感電させる、のように組み合わせの起点になるものを揃える。押すと予約され、硬直が明けしだい・届きしだい出る
- **近攻撃のほうが火力が出る:**遠攻撃は弾を避けながら撃てて楽なので、同じ手間なら近攻撃が勝つようにする(DPSで1.6倍以上を目安)。近攻撃は振った範囲の敵の弾をかき消す
- **見切り・弾き:**ジャスト回避・ジャストガードの入力は置かず、確率で自動に見切る・弾くパッシブとしてビルドに入れる
- キーは全て変更できるようにする
- 武器の持ち方は装備で決まるため、戦闘中の持ち替えは置かない
- 手動で全スキルを撃つ操作(左右クリック・Q/E/R/F)は、比べるために試し斬り場に残している

スキルはアクティブ・パッシブそれぞれに、次の6分類を持つ。

| 分類 | アクティブの例 | パッシブの例 |
| --- | --- | --- |
| 近攻撃 | 錆びた大剣で薙ぎ払う | 出血中の敵への近接ダメージ増加 |
| 遠攻撃 | 散弾銃を撃つ、灰の矢を放つ | 残弾が少ないほど銃の威力が上がる |
| 付与 | 武器に腐敗を纏わせる | 炎上した敵に触れると毒も付与 |
| 召喚 | 死体から亡者を起こす | 召喚物が死ぬと周囲に瘴気が出る |
| 防御 | 灰の盾を張る | 瀕死のとき被ダメージを軽減 |
| 回復 | 血を啜って回復する | 正気度が下がるほど自然回復が増える |

分類も1つのタグとして扱い、「付与スキルを使った直後の召喚」のように分類同士を条件にできるようにする。

### 組み合わせの部品

ひらめきの種を増やすため、状態・属性・パラメータ・フィールドの種類はなるべく多く揃える。どの部品も、他の部品の条件として参照できるようにする。

| 部品 | 内容 |
| --- | --- |
| 属性 | 11種(下の一覧) |
| 状態 | 23種(下の一覧) |
| パラメータ | 筋力、技量、理力、信仰、体力、重量、残弾、正気度 |
| フィールドの環境 | 雨、砂嵐、霧、夜、瘴気、無風 |
| フィールドの状態 | 油溜まり、血だまり、水たまり、灰の堆積、死体、燃え跡、凍った床 |

組み合わせの例:雨で敵が濡れる → 感電の効果が倍 → 「感電した敵が死ぬと周囲に水たまりができる」スキルで連鎖させる。

### 属性と状態の一覧(34種)

属性11種はそれぞれ対応する状態を1つ持ち、さらに属性を持たない状態が12種ある。全ての状態は敵にも味方にもかかる。

| 属性 | 対応する状態 | 効果 | 噛み合う相手 |
| --- | --- | --- | --- |
| 斬 | 出血 | 動くたびにダメージ | 逃げ回る敵、召喚物 |
| 打 | 昏倒 | 蓄積が満タンで数秒行動不能、被ダメージ増加 | 凍結、鈍重 |
| 刺(銃弾を含む) | 露出 | 防御が下がる | 高火力の単発攻撃 |
| 火 | 炎上 | 継続ダメージ。濡れていると付かない | 油まみれ、油溜まり |
| 雷 | 感電 | 近くの敵に連鎖する | 濡れ、水たまり |
| 腐 | 腐敗 | 回復が反転してダメージになる | 回復する敵 |
| 呪 | 呪縛 | 受けたダメージの一部を解除時にまとめて受ける | 死の宣告 |
| 氷 | 凍結 | 蓄積が満タンで停止。打撃で砕くと大ダメージ | 打 |
| 闇 | 盲目 | 視界と命中が落ちる。背後からの攻撃が必ずクリティカル | 恐怖、背後攻撃 |
| 灰 | 灰化 | 蓄積で動きが鈍り、満タンで崩れる。死体が残らない | 死体ビルドへの対抗 |
| 血 | 渇き | 自分のHPを払って威力を出す。出血した相手から体力を吸う | 出血、瀕死 |

| 属性を持たない状態 | 付く条件 | 効果 |
| --- | --- | --- |
| 濡れ | 雨、水たまり | 炎上を防ぎ、感電を強める |
| 油まみれ | 油溜まり | 炎上の時間と範囲が倍 |
| 飢え | 戦闘の長期化 | 回復効果が半減 |
| 狂気 | 正気度が尽きる | 敵味方の区別なく攻撃が当たるが、火力が大幅に上がる |
| 恐怖 | スキルなど | 一定時間逃げ回り、背後攻撃の的になる |
| 瀕死 | HPが一定以下 | 「瀕死のとき」系の効果の起点 |
| 無傷 | 一度も被弾していない | 被弾した瞬間に解除 |
| 鈍重 | 装備重量の超過 | 移動が遅いが、打の威力が上がる |
| 死の宣告 | スキルなど | カウント0で即死。カウント中に倒すと周囲に呪縛を撒く |
| 加護 | 防御・回復スキル | 次の1撃を無効化 |
| 憤怒 | 被弾 | 被弾するたびに攻撃力が上がる |
| 静寂 | スキル、フィールド | アクティブスキルが使えない |

### 補正値のルール(暫定)

装備とパッシブスキルには補正値が付く。1つあたりの補正値の合計を-100%〜+100%に収めることで、どの装備も「総量はほぼ同じで、配分が違う」状態にする。

| 項目 | ルール |
| --- | --- |
| 補正値の範囲 | 1項目あたり-200%〜+200% |
| 項目の数 | 1つの装備につき、ランダムで1〜4種類 |
| 合計の範囲 | 全項目の合計が-100%〜+100% |
| 条件文 | 項目の1枠を使って入ることがある。1つの装備に1枠まで |

- **例:**火ダメージ+180%、移動速度-120%(合計+60%)
- **条件文の例:**炎上状態であれば2回攻撃できる(候補は付録Aを参照、200個)
- **狙い:**合計に上限があるため、補正値が全部高いだけの装備は出ない。厳選は「高い数値を探す」ではなく「欲しい配分を探す」になる

決定事項

- **合計の単位:**装備1つごとに-100%〜+100%
- **共通項目:**各装備に最大HP・移動速度・被ダメージなどの共通項目が必ず入る。使わない項目へのマイナスだけで得をしないようにするため
- **条件文のコスト:**条件文にも補正値換算のコストを持たせ、合計に含める。強い条件文ほど他の項目が下がる
- **低いほど強い補正:**実装する
- **極端な値:**上限は設けず、実装してみて困ったものだけ排除する
- **アーティファクト:**ランダムな装備とは別に、効果が固定された装備を用意する(候補は付録Bを参照、200個)

### 変わった条件の効果

補正値が高いだけの装備を延々と厳選させないため、数値の大きさ以外を条件にする効果を多く用意する。

- 装備の補正値の**合計がちょうど〇〇**のとき発動
- 補正値が**低いほど**効果が上がる(最低品質の装備に価値が生まれる)
- パラメータが**偶数/奇数**のとき
- 最も**低い**パラメータの値に比例してダメージが増える
- 装備の**重量が0**、または**所持品が満杯**のとき
- **正気度が低いほど**火力が上がり、被ダメも増える
- 周囲の**死体の数**に応じて効果が変わる
- 直前に**別の属性**で攻撃したときだけ発動(属性を交互に使わせる)

### ビルドが一辺倒にならないための調整

「物理だけに振るのが結局強い」を防ぐため、単一の方向に特化するほど伸びが鈍る仕組みと、混ぜるほど得をする仕組みを両方入れる。

- **同種の補正は加算、異種の補正は乗算:**同じ「物理+%」を重ねても伸びは緩やか。違う種類を掛け合わせると大きく伸びる
- **敵の耐性を分散させる:**どの属性にも強い敵と弱い敵がいて、単一属性では詰まる場面を作る
- **隠れた最適解を探すシミュレーター:**戦闘ロジックを分離しておき、全組み合わせを自動で戦わせて、突出したビルドや使われない部品を開発中に洗い出す
- **上方修正を基本にする:**強すぎるビルドを弱めるより、使われない部品を強くして釣り合わせる。見つけた「最強ビルド」が消える失望を避けるため

## 遠征隊(放置)

放置の形は遠征隊にする。キャラを行き先に送り出すと、帰ってきたときに経験値・装備・新しいスキルを持ち帰る。遠征中のキャラは戦えないので、キャラを何人も作って回す。

| 行き先(試作) | 時間 | 手強さ | 環境 | 出やすい物 |
| --- | --- | --- | --- | --- |
| 野営地の見回り | 2分 | 60 | なし | 少し |
| 灰の街道 | 30分 | 120 | 敵は雷に強い | 斬・出血・移動の物、出血や駆ける刃の条件文 |
| 錆の廃坑 | 2時間 | 220 | 油溜まりの床、敵は火に強い | 武器(大剣・斧・連枷・投石紐)、火と炎上の物 |
| 沈んだ聖堂 | 8時間 | 400 | 雨、敵は斬に強い | 雷・感電の物、条件文つきの装備、雷と雨の技 |

- **ビルドで持ち帰る量が変わる:**帰還したとき、そのキャラのビルドで、その地の環境(雨・床・敵の耐性)のまま案山子の群れと短く戦わせ(早回し)、DPSを測る。行き先の手強さより強いほど多く持ち帰る(0.3〜1.5倍)。行き先ごとにビルドを考える理由になる
- **負傷:**測った強さが手強さの70%に満たないと、負傷して戻ることがある(足りないほど起きやすく、最大80%)。負傷の間(遠征の時間の半分、最短5分)は戦えず、遠征にも出せない
- **経験値:**長い遠征ほど時間あたりの経験値が多い。Lv50までは、聖堂へ手強さどおりの強さで通って60時間ほど(試作の値)
- **スキルは遠征で覚える:**覚えたスキルはアカウント全体で共有し、どのキャラでも使える。最初は基本の技・塗油・パッシブ4つ・雨乞いの鈴だけ覚えている
- **装備は拾い物の山へ:**持ち帰った装備は全キャラで共有する
- 同じ遠征なら同じ物を持ち帰る(出たときの乱数の種で決まる)

## 試行錯誤を軽くする仕組み

ひらめいたらすぐ試せるように、組み替えと別キャラの作成はほぼ無料・ワンタッチにする。集めた部品はアカウント全体で共有する。

- **組み替え無料:**装備・スキル・作戦・切り札の付け替えにコストをかけない
- **能力値はキャラの個性:**能力値は放置で育ち、振り直しはできない。別の振り方を試すときは、キャラを気軽に増やす
- **1キャラ1ビルド:**ビルドの切り替えはキャラの切り替えで行う(プリセットは置かない)
- **部品の共有:**集めたスキルと装備は全キャラで使える。新キャラも、すぐ既存の部品で組める
- **試し斬り場:**天候・床の状態・敵の状態・耐性を自由に設定できる案山子を置き、実戦前に組み合わせを確かめられる
- **ビルドコード:**文字列で書き出し・読み込みでき、仲間と見せ合える

### 与ダメージの表示

「何が効いたのか」が分からないと、ひらめきが再現できない。表示は気持ちよさと分析の2段にする。

- **戦闘中:**ヒットごとの数値を属性の色で表示。連鎖や条件が発動したヒットは大きく、発動したスキル名を添える
- **コンボ:**相互作用・条件文・連鎖が噛み合ったヒットは「雷雨」「血雷」のようなコンボとして名前を出し、続いた数(〇連)も出す。コンボの種類はデータで足せる
- **戦闘後:**スキル・属性・条件ごとのダメージ内訳とDPSを表で出す。「全体の何%がどの連鎖から出たか」が分かるようにする
- **COOP:**仲間ごとの内訳と、シナジーで上乗せされた分を分けて表示する

## 敵・ボス設計

高難度の敵は「ビルドへの問い」として作り、1つのビルドで全部に勝てないようにする。腕前だけで突破できる敵ばかりだと、ビルドの価値が下がるため。

| ギミック | ビルドへの問い | 苦戦するビルド |
| --- | --- | --- |
| 被弾ごとに攻撃力が上がる | 少ない手数で大ダメージを出せるか | 多段ヒット・持続ダメージ |
| 状態異常無効 | 変換や素の火力で対応できるか | 状態異常依存 |
| 召喚物を優先して狙う | 本体の火力と耐久があるか | 召喚 |
| 避けきれない全体攻撃 | 耐久をビルドで用意したか | ガラスキャノン |
| 一定時間内に倒さないと全滅 | 火力を十分に積んだか | 耐久特化 |

- 腕前で避けられる攻撃と、ビルドでしか受けられない攻撃を1体のボスに混ぜる
- 挑戦前にボスのギミックを開示し、ビルドの組み替えを促す

## COOP設計

2〜4人のリアルタイム協力を想定し、他のプレイヤーのタグを参照できる効果で「組んで初めて完成するビルド」を作れるようにする。

- **シナジー効果:**「味方が凍結させた敵に追撃」「味方の召喚物にも自分のバフが乗る」など、他人のタグを条件にする
- **役割:**固定職業は置かず、ビルドの結果として前衛・火力・支援が自然に分かれる形にする
- **人数による調整:**ボスの体力とギミックの数を人数に応じて増やす
- **戦利品:**ドロップは個人ごとに出し、取り合いを起こさない
- **ソロ:**ソロでも遊べるように、自分専用の調整を入れるかは未決

## 技術構成

描画はPhaser 3、通信はColyseus(Node.js)で組み、ダメージ計算は描画から切り離した共通ロジックにする。

| 部分 | 技術 | 担当 |
| --- | --- | --- |
| 描画・入力 | Phaser 3(TypeScript) | 自キャラの移動、エフェクト、UI |
| 通信 | Colyseus | 部屋の管理、状態の同期 |
| 戦闘ロジック | 共通TypeScriptモジュール | タグ・トリガー・変換を含むダメージ計算 |
| 保存 | サーバー側DB(未決) | キャラ、装備、放置の進行 |

- **同期の方針:**自キャラの移動は各画面で即座に反映し、スキルの発動(作戦)・敵の行動・ダメージ判定はサーバーが決める。タイミングの判定がシビアでないため、通信の遅れが手触りに響きにくい。協力プレイなのでチート対策は最小限でよい
- **放置と戦闘を同じ計算にする:**作戦で戦うので、入力なしでも戦闘が進む。放置の進行もシミュレーターも、同じ戦闘を早回しして求める。乱数は種つきにして再現できるようにする
- **計算の分離:**ダメージ計算は純粋な関数にして、単体テストとバランス調整用のシミュレーションを回せるようにする
- **放置の計算:**オフライン中の進行は、ログイン時に経過時間からサーバーでまとめて計算する

## 試作マイルストーンと未決事項

最初の試作は3段階で、「眺めて・避けて気持ちいいか」と「組み合わせが面白いか」を早めに確かめる。

1. **ソロ戦闘:**1人で動かせて、スキル3つ・タグ5種・フィールド状態2種程度で組み合わせが変わる。試し斬り場と与ダメージの内訳表示もここで作る
2. **2人同期:**2人が同じ部屋に入り、移動と攻撃が同期する
3. **ボス1体:**ビルドへの問いを持つギミックを2つ以上入れる

未決事項

- 世界観の具体像(舞台となる場所、勢力、主人公の立ち位置)
- ゲームパッドに対応するか
- 作戦の行数の上限、条件の種類を進行で解放するか
- スキル枠15個を最初から全部使えるのか、進行で解放するのか
- 放置要素の遠征隊以外の形(工房など)
- 保存先のデータベース
- ソロプレイ時の調整の有無
- アーティファクトを装着できる部位(試作では暫定で装飾品の枠)
